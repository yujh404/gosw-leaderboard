# GOSW Sports Festival 2026

경기오산소프트웨어고등학교 2026 체육대회 실시간 리더보드다. Next.js App Router, React, Neon PostgreSQL, Vercel을 사용한다.

## 화면과 기능

- `/`: 학생 공개 리더보드. 총점 순위, 종목 탭, 경기 상태, 설명·규칙, QR 공유·다운로드, 전체화면을 제공한다.
- `/leaderboard`: 공개 리더보드로 이동한다.
- `/admin`: 인증된 교사의 종목·점수 관리 화면이다. 이름, 사진, 설명, 규칙, 상태와 순서를 편집한다.
- `/admin/login`: 교사 아이디·비밀번호로 로그인한다. 공개 회원가입은 제공하지 않는다.

| 반  | 학과             | 색상 |
| --- | ---------------- | ---- |
| 1반 | 소프트웨어개발과 | 보라 |
| 2반 | 소프트웨어개발과 | 하늘 |
| 3반 | 임베디드학과     | 라임 |
| 4반 | 임베디드학과     | 주황 |
| 5반 | 정보보안학과     | 분홍 |

## 점수와 실시간 동작

- 각 종목의 점수는 0~100,000 사이의 정수다. 5개 반 점수를 한 요청으로 원자적으로 저장한다.
- **대기중·진행중·완료 상태와 관계없이 입력한 모든 종목 점수를 총점에 합산한다.** 경기 상태만 바꿔서 점수를 숨기지 않는다.
- 동점은 `1, 1, 3` 형태의 공동 순위다. 같은 순위의 표시 순서는 반 번호순이다. 최초 0점에서는 모두 공동 1위다.
- 학생 화면은 요청 완료 후 3초 간격으로 확인한다. 일반적인 환경에서 저장 후 약 3초와 네트워크 지연 이내에 반영된다.
- 종합 1등이 바뀌면 열려 있는 안내·공유 창을 닫고 종합 순위 탭으로 전환한 뒤 순위표로 스크롤한다. 스크롤이 도착한 후 알림과 꽃가루를 표시한다. 공동 1등의 구성 변경과 첫 유효 점수로 1등이 정해지는 경우도 포함한다.
- 종합 1등이 유지되면 탭과 스크롤 위치를 바꾸지 않는다. 현재 선택한 종합·종목 순위의 상승 알림과 꽃가루는 기존 위치에서 표시한다. 최초 접속과 탭 이동 자체는 순위 변경으로 처리하지 않는다.
- 화면이 백그라운드일 때 확인을 쉬고, 다시 보이면 즉시 갱신한다. 연결이 끊겨도 마지막 점수를 유지하며 연결 상태를 안내한다.
- 종목·점수 수정에는 버전을 사용한다. 다른 교사가 먼저 저장했다면 `409`로 충돌을 알리고 덮어쓰지 않는다. 편집 내용을 보관한 뒤 창을 닫고 목록을 새로고침한다.
- 사진은 JPG·PNG·WebP, 최대 2MB·2,500만 화소다. 서버에서 실제 이미지를 검사하고 최대 1600×1000 WebP로 변환해 메타데이터 없이 DB에 저장한다.

## 설치와 환경변수

Node.js 22 이상(권장 24), pnpm 11을 사용한다.

```sh
pnpm install --frozen-lockfile
```

`.env.example`에 필요한 키를 정의한다. 비밀 값은 `.env.local`에만 저장하고 Git에 포함하지 않는다.

| 키                    | 용도                                                                       |
| --------------------- | -------------------------------------------------------------------------- |
| `DATABASE_URL`        | Neon의 pooled PostgreSQL 연결 문자열. Neon이 제공하는 SSL 설정을 유지한다. |
| `ADMIN_USERNAME`      | 교사 로그인 아이디                                                         |
| `ADMIN_PASSWORD_HASH` | scrypt 비밀번호 해시. 원문 비밀번호를 넣지 않는다.                         |
| `AUTH_SECRET`         | 최소 32자의 무작위 서버 전용 키. 로그인 제한 키의 HMAC에 사용한다.         |
| `NEXT_PUBLIC_APP_URL` | 선택 설정. QR 코드의 공개 origin이며, 미설정 시 현재 접속 origin을 사용한다. |

교사 비밀번호는 로컬 터미널에서 설정한다. 12자 이상 입력하며 입력값은 화면에 표시하지 않는다. 스크립트가 `.env.local`에 해시와 필요한 `AUTH_SECRET`을 저장한다.

```sh
pnpm admin:password
```

`.env.local`에서 `ADMIN_USERNAME`과 DB 연결 문자열을 설정한 뒤 실행한다.

```sh
pnpm db:migrate
pnpm dev
```

DB 초기화는 테이블을 생성하며 경기·점수 예제 데이터를 추가하지 않는다. `/admin/login`에서 로그인하고 실제 종목을 등록한다.

## Vercel · Neon 배포

1. Vercel에서 GitHub 저장소 `yujh404/gosw-leaderboard`를 연결한다. 프레임워크는 Next.js, 프로젝트 루트는 저장소 루트다.
2. Vercel Marketplace에서 Neon을 연결한다. 처음 설치하는 계정은 계정 소유자가 약관을 확인하고 동의한다. 무료 플랜의 지역은 사용 가능한 가까운 지역을 선택한다.
3. `DATABASE_URL`을 Development·Preview·Production에 연결한다. 미리보기에서 실제 점수를 변경하지 않도록 Neon의 별도 브랜치와 교사 계정을 권장한다.
4. Vercel 환경변수를 `.env.local`로 가져온다. 기존 로컬 교사 설정이 있으면 먼저 안전하게 보관한다.

```sh
pnpm dlx vercel link
pnpm dlx vercel env pull .env.local
```

5. `pnpm admin:password`로 계정을 준비하고 Vercel에도 `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH`, `AUTH_SECRET`을 설정한다. 원문 비밀번호는 Vercel에 저장하지 않는다.
6. 운영 DB를 대상으로 `pnpm db:migrate`를 한 번 실행한다. 배포 빌드가 자동으로 스키마를 변경하지 않는다.
7. `pnpm verify` 후 배포한다. 기본 QR은 현재 접속 도메인을 사용한다. 항상 특정 공개 도메인으로 공유하려면 `NEXT_PUBLIC_APP_URL`에 해당 origin을 설정하고 다시 빌드·배포한다. `NEXT_PUBLIC_` 변수는 빌드 시점에 반영된다.
8. 공개 도메인의 QR 코드와 실제 교사 계정으로 점수 저장 → 별도 학생 브라우저의 순위 갱신을 확인한다.

`vercel.json`은 서울(`icn1`)에서 서버 함수를 실행하도록 설정한다. 실제 적용 가능한 지역·플랜은 Vercel에서 확인한다.

## 검사

```sh
pnpm verify
pnpm audit --prod
```

`verify`는 ESLint, 타입 검사, Vitest, 프로덕션 빌드를 실행한다. 순위·동점·합산·순위 상승, 점수·종목 검증, 비밀번호 검증을 단위 테스트한다.

실제 브라우저 E2E는 **전용 로컬 PostgreSQL `gosw_e2e`**를 사용한다. 매번 해당 DB의 앱 테이블을 비우므로 운영 DB를 지정하지 않는다. 설정은 loopback 주소와 DB 이름을 확인해 다른 DB의 사용을 거부한다.

```sh
docker run --detach --rm --name gosw-leaderboard-e2e \
  --publish 127.0.0.1:55426:5432 \
  --env POSTGRES_USER=gosw_test \
  --env POSTGRES_PASSWORD=gosw_test \
  --env POSTGRES_DB=gosw_e2e postgres:17
pnpm test:e2e
docker stop gosw-leaderboard-e2e
```

E2E 명령은 먼저 공개 QR 주소를 테스트 서버(`http://localhost:3108`)로 설정해 프로덕션 빌드를 생성한다. 로컬에 운영 공개 주소가 설정돼 있어도 QR 검증이 운영 사이트로 향하지 않는다. 로컬 E2E는 설치된 Google Chrome을 사용한다. CI에서는 Playwright Chromium을 설치해 사용한다. 테스트 전용 계정과 서버 환경은 `playwright.config.ts`에서 격리하며 운영 DB·교사 계정을 사용하지 않는다.

E2E는 교사 로그인, 사진 업로드, 종목 등록·정렬·상태 변경, 점수 저장, 독립된 학생 브라우저 2개의 갱신과 꽃가루, 경기 규칙, QR 다운로드, 모바일 레이아웃, 저장 충돌, 인증·교차 출처 차단, 로그아웃, 재연결, 로그인 시도 제한을 검증한다. 화면 캡처는 `test-results/`에 생성한다.

GitHub Actions는 PR과 `main` push에서 위 검사와 격리된 PostgreSQL 기반 E2E를 실행한다.

## 운영 참고

- 세션은 12시간 유효하며 HttpOnly·SameSite 쿠키를 사용하고 운영에서는 Secure를 설정한다. DB에는 세션 토큰의 SHA-256 해시만 저장한다.
- 모든 종목·점수·사진 변경 API에서 교사 인증과 요청 origin을 검사한다. 클라이언트 화면 숨김에만 의존하지 않는다.
- 비밀번호는 scrypt로 해시한다. 로그인은 Vercel이 제공하는 클라이언트 IP의 HMAC별로 10분간 10회 제한하며 DB에 저장해 여러 함수 인스턴스에서 공유한다. 로컬에서는 공통 테스트 제한을 사용한다.
- 비밀번호 변경 후 기존 로그인도 종료하려면 운영 DB에서 `DELETE FROM sessions`를 실행한다. 다음 접속부터 새 비밀번호가 필요하다.
- 종목 삭제나 전체 점수 초기화는 실수 방지를 위해 UI에 제공하지 않는다. 점수 정정은 해당 종목의 점수 입력 창을 이용한다.
- 사진 변경 과정에서 종목에 연결되지 않은 업로드가 남을 수 있다. 행사가 끝나면 백업 후 미사용 사진을 정리한다.
- 사용자 기기의 모션 감소 설정을 존중해 꽃가루·순위 이동 애니메이션을 줄인다.
